01 / TOPOLOGY

机器之间是双树，机器内部是链

树 A 的节点连接为 0 → 2，2 → 1、3；树 B 镜像为 3 → 1，1 → 2、0。箭头表示父 → 子。每个节点的局部 GPU 顺序在本例固定为 0 → 1 → … → 7。

这是一种符合源码的连接实例。真实 intra 顺序、channel 数和模式由拓扑搜索决定；没有假设所有 GPU 都被排成完全二叉树。

02 / EXECUTION

先满足依赖，再传递结果

非叶节点收齐当前 chunk 的所有孩子贡献后，合并自己的输入并上送。根节点生成最终结果后立即下发；中间节点保存结果并继续广播。

runTreeSplit() 将非根节点的线程划为归约组和广播组，根节点融合接收、归约、存储和发送。这里的双树与线程 split 是两个不同层次。

动画按 chunk 表达依赖，省略协议 slice、FIFO credit 和设备线程细节。4 MiB 是教学分块，实际 chunk 大小由协议与调优决定。时间单位为逻辑 tick：本地边 1、跨机边 2，同向同边 FIFO；并非 GPU 实测耗时或 NIC 带宽仿真。

03 / COST

双树均衡负载，不增加逻辑数据量

每棵 GPU 树有 31 条边，其中 28 条节点内边、3 条节点间边。每棵处理 M/2；每条边归约一次、广播一次。

全体发送量 = 2 × 31 × M = 1,984 MiB
跨节点发送量 = 2 × 3 × M = 192 MiB

节点级树 A 的中间节点 2，在树 B 中变为叶节点；节点 1 则相反。互补关系发生在跨节点骨架上，节点内链的 GPU 不一定互换角色。

源码对应、输入约定与完整连接表

每个 chunk 的每个元素取相同演示值：(rank + 1) × (chunk 编号 + 1)。因此 A0～A3、B0～B3 的逐元素结果依次为 528、1056、1584、2112、2640、3168、3696、4224。每块都保留全部 32 个 rank 的贡献。
